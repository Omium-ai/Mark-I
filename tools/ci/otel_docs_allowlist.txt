# otel_docs_allowlist.txt — the reviewed baseline for 02 §9's second CON-005 acceptance
# clause: "grep of docs finds no OTel-as-dependency reference".
#
# Scope is every markdown file we author, not just docs/ — 02 §9 says "docs", but an
# OTel collector documented in deploy/README.md is exactly the reference the clause
# forbids and exactly the one a docs/-only scan cannot see. Build output and vendored
# trees (dot-directories, node_modules, target) are pruned.
#
# WHAT IS SCANNED, AND WHY IT IS NOT A BARE GREP. A bare grep for "OpenTelemetry" is
# useless here: ADR-0005 exists to argue against OTel and names it 25 times, correctly.
# What the clause forbids is a *dependency* reference, so the scan matches PACKAGE
# IDENTIFIERS and nothing else -- go module paths, crate/npm names, the OTEL_ env-var
# family. English prose about OpenTelemetry is not a dependency and passes freely.
#
# WHY AN ALLOW-LIST AND NOT A CLASSIFIER. Every entry below is a NEGATIVE reference: an
# identifier appearing inside a ban list, a lockfile scan pattern, or a description of
# this gate. A heuristic that tried to tell "banned here" from "required here" would be
# guessing at intent from syntax. An enumeration cannot guess -- and a new identifier
# line has to arrive as a reviewed diff, which is the whole control.
#
# THE SET MUST MATCH EXACTLY, both directions. A new line fails (unreviewed reference);
# a vanished line fails too (an allow-list nobody must prune is a permanent waiver, the
# failure mode traceability-debt.txt's header spends a paragraph on). Format is
# path<TAB>whitespace-squeezed line text, so re-flowing a paragraph churns this file and
# renumbering a document does not.
docs/11-observability-and-slo.md	- **Binary size and dependency surface.** The edge budgets are brutal on purpose: `mark1-proxy` ≤35 MB RSS and ≤1 ms median added latency; `mark1-hookshim` is a static binary with a ≤10 ms cold start and no async runtime at all (04 §5). `opentelemetry` + `opentelemetry-otlp` + `tonic`/`hyper` exporter stacks pull tens of crates and an exporter runtime into binaries whose whole design brief is "boring, small, auditable." The shim *cannot* take a tokio dependency for a metrics exporter — it deliberately has no runtime.

A gate that red-flags its own rationale is a gate someone deletes | lead | **closed, four mutations watched red.** The move is to scan for **package identifiers**, not the English word: `go.opentelemetry.io`, `@opentelemetry/`, `opentelemetry[-_.]x`, `x-opentelemetry`, `OTEL_[A-Z_]+`, `otlp[-_]x`. Prose about OpenTelemetry is not a dependency and never fires; a module path is one regardless of the sentence around it. That cuts 112 fuzzy hits to **15 exact ones**, and every one of the 15 is a NEGATIVE reference — an identifier sitting inside a `cargo-deny` ban list, a lockfile scan pattern, or a description of this gate. Those 15 are enumerated in `tools/ci/otel_docs_allowlist.txt` and the gate requires **exact set equality** in both directions: a new line is an unreviewed reference, and a vanished line is failed too, because an allow-list nobody has to prune is precisely the permanent waiver `traceability-debt.txt`'s header spends a paragraph warning about. **Case-sensitive on purpose** — `otel_gate.sh`, this file's own name, appears in three documents and is not an identifier; a gate that flags itself trains people to ignore it. **Scope widened past the literal clause:** the scan covers every authored `.md`, not just `docs/`, because an OTel collector documented in `deploy/README.md` is exactly the reference the clause forbids and exactly the one a `docs/`-only scan cannot see (verified: zero identifier hits outside `docs/` today, so the widening costs no allow-list entries). Mutations: a doc introducing `go.opentelemetry.io/otel/sdk` fails with `+`; a phantom allow-list entry fails with `-`; deleting the allow-list fails with *"the doc half of CON-005 is unchecked and silently green"*; and a probe planted in `deploy/` fails, which is what proves the widening is load-bearing rather than cosmetic. **CON-005 is now fully proven and was struck from `traceability-debt.txt`** (66 baseline, 54 now). The same gate citation also closed `NFR-OPERABILITY-002`'s *"dependency-scan clause is Go-only"* partial — 02 §9 says that row's scan is *shared with CON-005*, and the shared artifact covers rust, go and python; only its `cmd/main.go` obs-wiring partial (D-CP) remains |

docs/spec/architecture-inputs.md	- Cursor's enterprise telemetry export is **"OTLP/HTTP binary protobuf. gRPC and JSON are not supported"** — i.e. even a company with unlimited resources ships device/server telemetry as protobuf-over-plain-HTTPS-POST, not gRPC. No prompt content is ever exported. Event families are admin-toggleable. ([cursor.com/docs/enterprise/opentelemetry-export](https://cursor.com/docs/enterprise/opentelemetry-export))
