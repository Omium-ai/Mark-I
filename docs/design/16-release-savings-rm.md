Status: approved by the founder 2026-09-26. Builds on `15-teams.md` (branch `teams-v1`). This is the contract every lane builds against; a lane that must deviate says so in its report instead of improvising. Research behind every section: `Omium/scratch/release-research/README.md`, `Omium/data/rm/papers/rm-design.md`, `Omium/data/rm/papers/verifier-models.md`, `Omium/data/rm/manifests/LICENCE_AUDIT.md`.

## Founder rulings

1. **Certification by a trained T2 reward model (RM)**, not gold labels standing in. The third independent view is **both** a diff-reading judge **and** a second RM from a different model family.
2. **The RM runs on the user's machine or in our cloud — the user chooses** (Settings). Local is the default where the machine can run it; nothing leaves the machine on the local path.
3. **Cloud judging and memory extraction go through the platform llm-router (Nebius Token Factory)**, not an Anthropic key. Zero Data Retention is on (founder toggles it in the Nebius console); processing region is "global" and the consent text says so.
4. **"Tokens saved" is measured against plain Claude Code**: net estimated savings (credit blocks that led to a fixed task, debit tokens spent after blocks that did not). It can be negative. Arrests are reported separately as "forced retries avoided".
5. **Training data**: public data first (licence-clean rows only until counsel signs off on model-generated rows and unlicensed archives), then real agent PRs mined from GitHub, then self-generated execution-labelled sessions, then Mark 1 users' outcomes with consent.
6. Teams: per-member aggregate totals (sessions, verified tasks, tokens, saved) are visible to every member; never another member's sessions. Invite emails go out via Customer.io. The weekly savings email is **opt-in**.

## Independence rules (Paper II Assumption 1) — every lane obeys these

- Views: **anchors** (the project's own static checks; compile/test are the sound rejectors), **judge** (LLM), **RM-A** and **RM-B** (two trained models of different base families).
- The RM sees **only the task text and the final diff**. Never anchor output, EvidenceRecords, test output, the agent's trajectory or self-claims, or judge output. A unit test on prompt assembly enforces it.
- The judge counts as independent of anchors **only** when its input is the diff (E1 hunks or local raw diff) and its rubric rows used for estimation do not reference anchor output. An E0 judge (anchor rows as evidence) is correlation group `syntactic`.
- Correlation groups come from `m1_verifiers.definition.group`, not from the event family. Tests are their own group (architecture spec), not `syntactic`.
- Identifiability gate G4 counts only sound rejectors (compile, test) as anchors.
- RM training labels are execution- or time-grounded only (tests, merge/revert/CI/survival, human gold). Never Mark 1's fused verdicts, never LLM-judge labels.
- Every view runs on every task it can (no ambiguity-triggered running).

- Edge as built (L6a, `go/mark1d/internal/rm`):
  - **Models.** `mark1-rm-a` = RM-A on qwen2.5-coder-1.5b, `mark1-rm-b` = RM-B on IBM granite-4.0-1b-base. Artifacts at `https://dl.omium.ai/mark1/models/rm/<name>@<ver>/{model.gguf,manifest.json}`; the manifest is `training_jobs/rm/export.py` `edge_manifest` verbatim: `{name, version (JSON integer ≥ 1), sha256, size_bytes, calibration_version, template_sha, eval_card_sha, execution_hash, scoring{method:"logit_diff", yes:" yes", no:" no"}}`. The edge embeds the same objects in `catalog.json` (strict decode: an unknown field or a string version fails the whole catalog), serves the newest valid entry per name, and deletes any download that misses `sha256`/`size_bytes`.
  - **Runtime.** llama.cpp **b11193** CPU build, sha256-pinned per platform in `tools/release/fetch-rm-runtime.sh`; export converts with the same tree's `convert_hf_to_gguf.py` + `gguf-py`. One `llama-server` child per model, independently supervised (crash-loop breaker per child), loopback with a per-start API key, `-np 1 -c 4352 --cache-ram 0 --ctx-checkpoints 0 --prio -1`, half the cores, one inference at a time across both. `WeightsBudget` 4 GiB: the measured Q8_0 sizes are 1.65 GB (RM-A) + 1.74 GB (RM-B) = 3.38 GB. Revoking `local_rm` stops both children and any download mid-stream; `mark1 off` cancels the session and kills both.

  - **Input.** rm-input/v1 rendered by `prompt.go`, a line port of `training_jobs/rm/prompt.py` (`MAX_DIFF_CHARS` 9000; the claim/suppression regexes and path case-folding carry Python's Unicode `\b`, `\s`, `(?i)` and `str.upper/lower` semantics) over the task text and the redacted task diff only: `anchors.Runner.TaskDiffFor`, from the HEAD recorded at the task's open, so work the agent committed itself is included. Token ids are built as `objective.encode`: `/tokenize(prefix, parse_special=false)[:4096 − len(suffix)] + /tokenize(SUFFIX, parse_special=true)`, no BOS, sent to the runtime as ids, so the server never tokenizes or truncates on its own. `parse_special=false` is HF's `split_special_tokens=True`: control tokens stay text, user-defined added tokens (Qwen's `<tool_call>`) still match.
  - **Score.** export.py's `SCORE_REQUEST` with `logit_bias` +100 on both answer ids (each a single token, else the model abstains); `s = ln p(" yes") − ln p(" no") = logit(" yes") − logit(" no")` at the final position; `RmScore.score = σ(s)` ∈ [0, 1], uncalibrated; the adjudicator recovers `s = log(p/(1−p))` and applies `calibration_version`.
  - **Execution hash (rm-exec/v1), one recipe end to end.** `execution_hash = BLAKE3-256(B)`, hex, where `B` is, byte for byte: the GGUF file's bytes, then `0x00`, then the ASCII runtime identity `llama.cpp b<build>` (the build number the binary prints in `llama-server --version`, `(build 11193, …)`, identical on every platform's build of one tag), then `0x00`, then `template_sha` as 64 lowercase hex ASCII. Known-answer vector: GGUF bytes `GGUF rm-exec/v1 vector`, runtime `llama.cpp b11193` ⇒ `32a997ee8842d4906314d2175efa4b9b5d83c2def873f4577dbe12758db03fea` (asserted in Go and in training-jobs). export.py computes it on the pinned runtime (refuses to export on any other build) and writes it into the manifest; the edge recomputes it after the sha256 check and **refuses** (state `refused`, not served, doctor fails, the other model keeps scoring) a model whose hash differs; `RmScore.execution_hash` carries it; publish seals it as `artifact.execution_hash` = `effective_execution_hash` (m1_103; supersedes m1_098's `execution_sha256`); the adjudicator counts a client-side RmScore only when its `execution_hash` equals the sealed hash of that model id (`refused_rm_execution_hash`, `refused_rm_unsealed` otherwise, counted in `rm_refused_total`, never silently); a `CLOUD` row is checked the same way, because the cloud deployment serves the same sealed GGUF on the same runtime and so carries the same hash.
  - **Granite.** granite-4.0-1b-base is HF class `GraniteMoeHybridForCausalLM` with all 40 `layer_types` = attention and no experts, so b11193's converter rewrites it to GGUF arch **`granite`**, not `granitehybrid` (that arch is the Mamba2 `-h` checkpoints). Converted and Q8_0-quantized with b11193 it loads and scores on the b11193 CPU build; a loader or pin that expects `granitehybrid` for this model is wrong.
  - **Status.** `<state>/rm/status.json` carries the worst served model's state plus one row per model (`starting|downloading|verifying|ready|no_runtime|download_failed|failed|refused|not_served`); `mark1 status` prints one line per model and `mark1 doctor` fails `rm_runtime` only on a crash loop, a failed pinned download or a refused execution hash, naming which model.
  - **Parity.** `testdata/parity.json` (render cases) and `testdata/export-parity-{a,b}.json` (export.py `parity()` on the two base models, Q8_0 on b11193) are generated by `testdata/gen_parity.py` from the training package; Go asserts identical renders offline and, with `MARK1_RM_LIVE_{SERVER,GGUF,PARITY}`, identical token ids and scores through the real child.

### L7 — Diff-reading judge
- Edge judge (customer's key) reads the local raw diff + task text with a rubric whose estimation rows never reference anchor output; cloud `@2` reads E1 sanitized hunks for consenting tenants. `JudgeVote` gains `tier_used` and `trigger`. E0 judge rows are group `syntactic`.
- Edge diff judge scope (`mark1d internal/judge/diff.go`, wired in `cmd/main.go`): its input is the E1 input — `contrib.FilterDiff(TaskDiffFor(task, repo), repo, root)`, so a section outside the enabled root, `.mark1ignore`d or secret-named never reaches it — then the admit axis. It runs only for sessions whose agent is Claude Code (`judge.DiffJudgeAgent`, from the tailer's session table, else the hub's SessionStart): the key it spends is the customer's Anthropic key, and nothing the person consented to sends Codex, Gemini, Copilot, opencode, Cursor or Crush code there; there is no per-agent opt-in, so every other agent's task gets no diff vote. Spend is capped per UTC day (`--diff-judge-daily-tasks`, default 40; `--diff-judge-daily-tokens`, default 500,000 estimated input+output tokens; negative turns the diff judge off); a task past either cap makes no call and is counted in `<state>/judge/diff_budget.json` (`skipped`), the first skip of the day logged.
- `@2` is seeded in the catalog by m1_100 (`group` `judge`, `e0_fallback.group` `syntactic`). Estimation splits its votes by the evidence they read: E1 votes are the `judge` column, E0-fallback votes the separate column `judge:grounded-rubric@2/E0` in `syntactic`. Fusion keys by the same column: `NormalizedVote.column`/`group` (set by `readjudicate.votes_by_task`) make an E0-fallback vote fuse on the `/E0` law in `syntactic` and an E1 vote on the `@2` law in `judge`; a tier with no estimated law fuses on the diff-rubric's calibrated judge prior, never the other tier's law. Cloud-side only: the edge never fuses `@2` (`judge:` ids are dropped from `verify`, and the verifier-id production forbids `:` and `/`), so no bundle grammar or conformance vector changes (06 §6.5).

### L8 — Real data (GitHub mining, self-generated sessions, consented user data)
- GitHub agent PRs: AIDev + a GH Archive collector (Claude Code/Codex/Copilot/Devin/Cursor signatures) with labels merged/closed, CI conclusion, revert, 30-day code survival; runs as cluster Jobs writing to `rm/raw/` + `rm/normalized/`.
- Self-generated: pilot 1,000 tasks (SWE-rebench/SWE-smith images) with an open agent on Token Factory models + a Claude Code slice, hidden-test labels, flaky re-runs, reward-hack detection; then 20k.
- Consented user data (v2): a consent class "Contribute task outcomes to improve Mark 1's models" (off by default) that uploads task text + redacted diff + outcome for opted-in devices; dogfood tenants first. The nightly `rm/contributions/<tenant>.parquet` snapshot is SSE-KMS under its own key `alias/omium-prod-rm-contributions` (Omium-platform `envs/prod/training_plane_irsa.tf`): intel (`omium-prod-mark1-intel-irsa`) encrypts with a single-part PutObject naming the key's ARN (`app/corpus/contributions.py put`: boto3 `put_object` with `ServerSideEncryption=aws:kms` and `SSEKMSKeyId=INTEL_RM_CONTRIBUTIONS_KMS_KEY_ARN`, required for an `s3://` root; pyarrow's writer is not used there because it HEADs the bucket, PUTs `rm/` and `rm/contributions/` directory markers and always uploads multipart, all of which the grant and the bucket policy deny), only `omium-prod-rm-assembly-irsa` (SA `omium-training-plane/rm-assembly`) decrypts. A dataset assembled with contributed rows is written by rm-assembly to `rm/datasets-private/<name>@<ver>/…` under the same key (single-part PutObject, `ServerSideEncryption=aws:kms`, `SSEKMSKeyId=<key ARN>`, each object ≤ 5 GiB) and read only by rm-assembly and the Nebius training job's IAM user `omium-prod-rm-training`; public-only datasets stay in `rm/datasets/`. The training bucket's policy denies both prefixes' objects and key names (listing into or above them, or without a prefix) to every other principal (10 §10.5a residual; the account root user keeps key administration and the bucket policy as break-glass); snapshot noncurrent versions expire at 30 d. Private datasets expire at 40 d (noncurrent 1 d later); a dataset using contributions is rebuilt from the latest snapshot at least every 30 days and training reads only the newest build, so a withdrawn row is gone from every private dataset within ~40 d.
- Consent follows the tenant, not the device (`mark1d internal/contrib`, `control/enroll.go`, `cmd/tenantswitch.go`): each pending record carries the tenant it was recorded under and `LabelDue` drops (and logs) one whose tenant is not the enrolled one; a tenant switch purges `<state>/contrib/`. `contribute_outcomes` is stamped with the tenant it was set under — `gates/contribute_outcomes.decided` for the person's own choice, `gates/contribute_outcomes.default` for an enrollment default — and on enrollment into another tenant (directly, after a sign-out, or by `mark1 enroll`, reconciled at every session start) it is turned off, undecided and its pending records purged; one set before any enrollment is adopted by the first tenant. A staff default applies only when the ACTIVE body carries `contribute_outcomes_default: true` **and** `contribute_outcomes_default_reason: "omium_staff"` (controld sets both for `DOGFOOD_TENANTS`), is journalled with `reason: default:omium_staff`, and never counts as the person's decision. Uploads wait until controld has acknowledged `contribute_outcomes` (`consents.Acknowledged`, the last record it accepted), not merely until nothing is pending.
- Consent relay across cloud versions (`mark1d internal/consents/relay.go`): the PUT body always carries every field explicitly, true or false (`e1`, `cloud_judge`, `training`, `team`, `local_rm`, `cloud_rm`, `contribute_outcomes`), because controld reads an absent later field as unchanged and an explicit false as off for this device (person-wide only on a true → false transition, 08 §3.7a); the answer's `consents` is the effective row, which the edge adopts before relaying again (`consents.Sync`/`Adopt`, `control/relay.go`): every field on in the body sent, off in the row and still on locally turns off in `gates/consents.json` exactly as a local off does (`e1` purges pending E1 parts, `contribute_outcomes` purges `<state>/contrib`, `local_rm` halts the RM child through its live consent read), journalled `reason: cloud_withdrawal`, listed in `GET /v1/optins` `cloud_withdrawal` until the person sets that key here again (persisted in `gates/consents_cloud_withdrawal.json`), and PUT at once with those fields false, which releases controld's hold; only that PUT's 2xx acknowledges the record. Relays are serialized (`relayMu`), so none PUTs a stale true after another's release. An on in the row is never adopted, except an undecided `contribute_outcomes` (after a tenant switch reset, relayed ABSENT so a round trip back to a tenant never sends the true → false that sweeps contributions) that the row still holds true: that is the device's own prior choice in this tenant and is restored and stamped decided (`restored_prior_choice`). An answer without `consents` (a legacy cloud) changes nothing. A record never stamped with consent copy 2 has `cloud_judge` and `training` turned off once at boot (`copy_reset`, listed in `GET /v1/optins` `copy_reset`, which also files controld's m1_107 `cloud_judge`/`training` reset when it is adopted before that stamp). Because a withdrawal made on another device changes nothing here to relay, the edge also PUTs its unchanged record at boot and at every session start (a SessionStart through the hub), which is when the held person-wide off comes back. The control API's `PUT /v1/optins` turns `cloud_judge`, `cloud_rm` or `training` on only for a request carrying `X-Mark1-Consent-Copy: 2` (the app showing the current register copy: Nebius/global judge, Baseten/us RM); without it such an enable is `409 {"error":{"code":"M1E-2014","reason":"consent_copy_outdated","message":…}}` with nothing written or journalled, so v0.1.14's "Anthropic, US" screen can no longer grant them through a new daemon. Turning any consent off, re-sending an on already held, and `e1`/`team`/`local_rm`/`contribute_outcomes` need no header. A controld that predates the later fields (prod f85bff9's strict decoder) 400s that body; the relay then resends the three it knows, so their withdrawals land, records that legacy acknowledgement (marked `legacy_cloud`, so the record stays pending) and backs off, and every later relay tries the full body first, so an upgraded cloud picks it up.
- Path axis parsing: a section's paths are read from the `diff --git a/P b/P` header only when its halves are the same path, else from the `---`/`+++`/`rename`/`copy` lines of its extended header (never a hunk line); C-quoted names are decoded; every path a section names (both sides of a rename) must pass, and a section whose paths cannot be read is dropped.
- Self-generation infra (`envs/prod/rm_selfgen.tf`) is gated by `rm_selfgen_enabled` (default `false`): an apply of the directory creates no selfgen resource until the founder approves the readiness review and flips it.

### Task diff — the one input the RM, the diff judge, E1 and contributions share (mark1d anchors)
- `Runner.TaskDiff` / the anchor diff facts: worktree against HEAD (3 lines of context; 0 for the envelope) **plus every untracked, non-ignored file** under the worktree as git's own new-file section (byte-identical to `git diff` of an intent-to-add path; `.gitignore`/`info/exclude` via git, `.mark1ignore` via `tailers.WorkspaceSet`; ≤ 1,000 files, ≤ 4 MiB total, a text file > 1 MiB shown as binary; sorted after the tracked sections). With no commit yet, every staged and untracked file is new. The user's index and worktree are never written (no `git add`, not even `-N`).
- Hardened git everywhere (10 §7.5): no repository-named program runs (filters emptied, submodules never entered, fsmonitor/hooks/attributes file/ext-diff/textconv/pager off, every transport refused by `GIT_ALLOW_PROTOCOL`), `--git-dir`/`--work-tree` pinned to the validated git dir and repository top (no embedded bare repository is ever discovered), a `.git` file followed only into a verified linked-worktree or submodule git dir and alternates only inside it (`unsafe_git_dir` otherwise), the person's global ignore file honoured (`core.excludesFile` resolved from their own global config, else `~/.config/git/ignore`), blame never skipping a repository's `ignoreRevsFile`, output shape pinned. Sandbox first on every OS without the write-confinement precondition (Linux without Landlock now works); the direct hardened read answers where the sandbox cannot host git (no userns — stock Ubuntu ≥ 23.10 —, no `sandbox-exec`, refused AppContainer, or a sandboxed git that cannot read the repository). Windows grants read on the repository top and the validated linked-worktree/submodule git dirs per run, revoked after it, never on a profile, program or drive root.
- Never silent: each empty diff has a typed reason (`no_change`, `not_a_repository`, `no_git`, `git_failed`, `diff_too_large`, `unsafe_git_config`, `unsafe_git_dir`) per worktree in `<state>/anchors/diff_status.json`, shown by `mark1 doctor` as `task_diff` (fails on the five that starve the views; names every read taken outside the sandbox).
- **Task-scoped base.** Each TaskOpen records its repository's HEAD (`anchors.Runner.Observe` → `OpenTask`, read off the event path, persisted in `<state>/anchors/task_bases.json` for 7 days so a restart mid-task keeps it; an R3 reopen keeps the first base). At close the diff is `git diff <open-HEAD>` — committed, staged and unstaged — plus untracked files. HEAD moved to a history the base is not an ancestor of (reset, rebase) ⇒ the merge-base; no common history (orphan checkout), the base garbage-collected, HEAD unborn again or the task opened in another repository ⇒ `base_unreachable`, never a silently wrong diff. A task opened before the first commit diffs against the empty tree. The anchors' envelope (suppression delta, touched set), the diff judge and E1 excerpts (both through `contrib.FilterDiff`, one shared closure), and contributions all read this same task-scoped diff (`TaskDiffFor`); the RM does too once its `Diff` takes the task (lead applies the rm call change).
- **Several repositories under one enabled folder.** Every task diff reads the session's own repository (`diffRepo`: the git top of the session's cwd when it sits inside the enabled root, else the root); contributions record that repository as `Top` (labels run there 30 days later) and `contrib.FilterDiff(diff, repo, root)` resolves paths against its top while still filtering to the enabled root.
- Linux hosts that restrict unprivileged user namespaces get the `omium-mark1d` AppArmor profile (09 §11.1).

## Withdrawal, task binding and the E1 read (review fixes, 2026-09-26)

- Withdrawal is per person within the tenant (07 m1_106, m1_107, 08 §3.7a): a field `PUT /api/v1/consents` turns from on to off on the sending device is written onto every device of the tenant enrolled by the same subject, and E1 parts and contributions are withdrawn where the field went off. A three-field body (edge ≤ v0.1.19, whose app granted `cloud_judge` and `training` under their old copy) lands a true for either as off and held. m1_107 resets every pre-release grant of either once, and the edge's copy-reset relay of both as `false` only releases the holds. The sweeps can now actually delete: controld's IRSA role gains `s3:DeleteObject` on `t/*/contributions/v1/*` and `t/*/evidence/v1/*` (it had quarantine only, so every withdrawal was AccessDenied and retried forever). The ingest bucket is versioned under a 35 d GOVERNANCE lock, so a deletion is a delete marker; the true copy for every surface is "removed within 30 days; deleted copies clear from version history within about 40 days".
- An E1 part is admitted only from the device that ran the task (the first TaskOpen/TaskClose to land binds it, `m1_task_devices`); unbound is a retryable 503.
- An attach and a withdrawal of the same device serialise on the device's consent lock, and the E1 read re-checks the device's latest consent per purpose: `GET /internal/v1/evidence/{task}?purpose=judge` needs `e1` + `cloud_judge`, `?purpose=rm` needs `e1` + `cloud_rm` (08 §3.8). The read has its own credential, `EVIDENCE_READ_TOKEN` (SM `omium/prod/mark1-evidence-token`), held by controld and the adjudicator only; intel's shared service token no longer reads E1.
- A device's `CLIENT_SIDE` `RmScore` must be signed (`rm_score_unsigned`, 422 M1E-2006 naming the event).
